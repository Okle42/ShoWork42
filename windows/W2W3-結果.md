# ShoWork42 Windows W2／W3 結果

分支 `windows-w1`（W1 之後接著做；功能分支 `w2-settings`、`w3-arrange`、`w2-island`、`w2-edge` 已合併）。
做法：先在 Engine 開接口（`Changed`、`StateChanged`、`Sessions`、`JumpTo`），四個功能各在自己的 git worktree 平行做、各自測試，
每個分支再由一位審查者挑毛病，合併後統一接線並修掉 23 項審查意見。

## 設定頁與光芒款式

- `%LOCALAPPDATA%\ShoWork42\settings.json`：三種狀態各自的開關、顏色、款式、亮度、寬度、速度；預設值跟 Mac 一樣。
  原子寫入；某一項壞掉只有那一項回預設、超出範圍夾回。改了立即套用，關掉的狀態不亮、視窗改亮下一個有開的狀態（同 Mac）。
- 款式的成本：
  - 呼吸（預設）：一個視窗、只畫一次、呼吸只改透明度，CPU 0.07–0.16%。
  - 會動的五種：改用目標四周四條點擊穿透的細長視窗，預先算距離／角度表，每幀只查表；15–30 fps 上限，看不到就不畫。
    每個約佔全機 0.4–1.0%（單核 3–8%）。
  - Windows「動畫效果」關閉時全部改成靜止光暈（對應 Mac 的減少動態效果）。
- 設定視窗跟隨 Windows 深／淺色；需要時才建立，關閉時釋放並整理記憶體。

## 自動排版

- 對象：可見、沒最小化、不在別的虛擬桌面、不是全螢幕的 conhost 與 WT 視窗；視窗歸屬中心點所在的螢幕。
- 排法與捨入跟 Mac 逐行一致（單元測試 59/59，含 Mac 的五種螢幕與兩種 Windows 工作區）。
- 觸發：終端機視窗數量改變（WinEvent，不輪詢；只在自動排版開著時才掛）或 Ctrl+Alt+L。
- **Windows 預設關**：裝好不會突然搬視窗；在設定頁或右鍵選單打開，或按 Ctrl+Alt+L 排一次。
- 排版不會啟動任何視窗；疊放時只把終端機插在前景視窗底下；前景是桌面、工作列之類時改放到一般視窗的最上層，不會排到桌面後面。
- 沒回應的視窗會跳過；移動用非同步的 SetWindowPos，疊放在背景執行緒做，卡住的視窗拖不住 agent。
- 最大化的視窗會先還原（不啟動）再排，跟 Mac「只跳過原生全螢幕」一致。

## 動態島（系統匣）

- 圖示：最急狀態的顏色＋數量；只有紅色時慢慢脈動（約 3 fps，預先畫好），其他時候不動。
- 左鍵 → 深色圓角面板貼在圖示旁（工作列在任何一邊、多螢幕、各種 DPI 都處理）：每個 AI 一列（狀態點、狀態、視窗標題、持續多久），
  點一下跳到那個視窗；↑↓／Enter／Esc 可用；失焦就關。
- 膠囊：進入「已完成／等你回答」時在時鐘上方淡入約 4 秒，不搶焦點；前景視窗本身不彈；一串事件合併成一顆（「+N」），紅不會被綠蓋掉；
  已經回答的會自動拿掉。

## 全螢幕邊緣光

四條 topmost、點擊穿透的細長視窗（3 px 實線＋內側漸淡，依 DPI 縮放）。紫色不上邊緣（同 Mac）。
有標題列的最大化、差 1 px、Alt+Tab／工作檢視都不算全螢幕。沒有動畫、沒有計時器。

## 出過的事（已處理）

合併接線後第一次跑 `w2_settings.ps1` 時，那個測試 agent 打開了自動排版，而它沒有白名單，
**把 Kang 的 WT 視窗搬動過一次**。已放回原本的位置與大小（沒有啟動、沒改疊放順序），事後比對跟一開始記錄的完全相同。
修法兩道：agent 只要是測試實例（設了 `SHOWORK_PIPE`），沒有 `SHOWORK_ONLY_WIDS` 就一律拒絕排版；該測試也加上只排名單內視窗的設定。

## 還沒做／注意

- 記憶體：設定視窗開著時穩定約 9–10 MB、打開瞬間不超過打開前的閒置值（約 44 MB）；有 UIA 用戶端操作時峰值 54–55 MB（`w2_settings.ps1` 以 200 ms 取樣檢查 < 60 MB）。
  做法：打開前先整理一次 working set、視窗顯示 1.5 秒後再整理一次——打開時碰過就不再用的頁面（JIT、控制項初始化、字型）不算在開著的成本裡。
  邊緣光亮著時 58 MB。平常閒置 30–45 MB。
- 測試保護：`tests/guard.ps1`——你自己的 agent 開著「自動排版」時，會開關終端機視窗的測試一律拒絕執行。
- 會動的款式多開幾個 CPU 會疊加；要再省可以降 fps 或改用 DirectComposition。
- 設定視窗開著時切換系統深淺色不會跟著變（重開視窗才變）。
- Ctrl+Alt+L 在某些鍵盤配置等於 AltGr+L；照規格保留。
- 沒實測：系統「動畫效果」即時切換（要改使用者的系統設定）、「開機時啟動」勾選真的寫入登錄檔（避免改到 Kang 的設定；只驗顯示與登錄檔一致）、
  邊緣光亮著時改顏色、膠囊切換到下一個 AI（這三項只看過程式碼）。

## W4 打包單一 exe

`windows\pack.ps1` 產生 `windows\dist\`（不進 git）：

| 檔案 | 大小 | 需要 | 閒置記憶體（裝好後） |
|---|---|---|---|
| `ShoWork42.exe` | 155.7 MB | 什麼都不用裝（內含 .NET runtime） | 57.5 MB |
| `ShoWork42-small.exe` | 1.7 MB | .NET 8 Desktop Runtime（沒裝時 Windows 自己跳出官方下載連結） | 57.7 MB |

- 兩個都內含原生版 `showork.exe`（hook 用），安裝時取出放在 agent 旁邊；安裝後 `bin` 裡只有兩個檔。
- 壓縮版（69 MB）試過不採用：啟動時把整個 runtime 解壓到記憶體，閒置 104 MB。WinForms 不支援 trim 與 NativeAOT，所以沒有更小的獨立版。
- 雙擊下載的 exe：先跳出說明視窗（會放到哪裡、會改 Claude 設定且先備份、開機啟動），按「安裝」才動手；已裝舊版就問要不要更新；同版本就只確認在執行。
- 列在「設定 > 應用程式」（HKCU，不需要系統管理員）：解除安裝會停 agent、拿掉 hooks（settings.json 回到原本位元組）、拿掉開機啟動與清單項目、刪掉 `bin`（exe 不能刪自己，由隱藏的 cmd 在結束後重試刪除）；光暈設定保留。
- 版本 0.4.0、圖示（`tools\make_icon.ps1` 產生）、檔案內容描述都寫在 exe 裡。**沒有程式碼簽章**：第一次執行 Windows SmartScreen 可能會警告（要買憑證才能消掉）。
- e2e `tests\w4_pack_e2e.ps1`：**42/42**。兩個 exe 各跑：雙擊只詢問不安裝、安裝、兩個檔且 showork 是原生版、hooks 指向安裝目錄且別的工具的 hook 還在、開機啟動與清單項目、裝好的 agent 在跑、照 settings.json 的指令經 Git Bash 執行 hook 讓測試視窗發綠光、記憶體、再裝一次不重複、從安裝目錄解除安裝、目錄刪掉、settings.json 逐位元組相同。
  全部在沙盒（`SHOWORK_HOME`、`SHOWORK_REG_ROOT`、獨立 pipe、假 settings.json），另外檢查使用者真的登錄檔與 settings.json 沒被動到。
- 修掉的 bug：`%TEMP%` 常是 8.3 短路徑（`C:\Users\ABCDEF~1`），跟行程回報的長路徑比對不起來，導致解除安裝停不了 agent；現在一律展開成長路徑再比。

## 光暈朝內（09-29，Kang 要光往視窗裡面照）

- 設定：`general.direction` = `inward`（預設）／`outward`；舊的 settings.json 沒有這欄 → 朝內；值壞掉只有它回朝內，自動排版不受影響。
  放在「一般」設定而不是每個狀態各自一份：方向決定光暈在視窗上面還是下面，一個視窗每幾秒換一次狀態，光暈不該跟著上下跳。
  設定頁「光暈」頁左下「光暈方向：朝內／朝外」，三張預覽卡立即換成對應的畫法（朝內時光畫在假視窗上面）。
- 畫法（寬度 1×，96 DPI，依 DPI 等比放大）：邊緣一條 2 px 實線（亮度 1× 時 alpha 0.55–0.85），往內是高斯漸淡，峰值只有 0.12–0.30，
  到 `Depth` 歸零：呼吸 24 px、流光 22、極光 26、漣漪 32、粒子／光霧 32（原本朝外的 pad 是 34–54）。圓角 8 px；最大化時直角。
  漣漪往內擴 24W、粒子往內飛、光霧的光團在 Depth 的內 3/4 平滑淡出（不會切出直線）。
- 視窗：靜止（呼吸）＝一個跟視窗一樣大、中間全透明的 layered window（呼吸只改常數 alpha，每幀一次呼叫，跟朝外一樣）；
  會動的五種＝視窗內緣四條（上下全寬、左右夾在中間，不重疊），中間完全不蓋。
- 疊放：插在「目標上面那個視窗」底下（跳過自己的條）；上面是 topmost 或沒有視窗時用 `HWND_TOP`；光暈永遠不是 topmost。
  目標本身是「永遠在最上層」的視窗時光暈沒辦法在它上面，這時不反覆重排（每 250 ms 不做事）。
- 測試：`w2_glow.ps1 -Direction inward` 31/31（六種款式：蓋住目標可見範圍 ±0 px、目標正上方、WindowFromPoint 在光暈帶內打到目標、
  切換前景到另一個測試視窗再回來後 1–35 ms 內回到正上方、最小化隱藏）；`-Direction outward` 19/19；`w0_e2e.ps1` 朝內 24/24、朝外 22/22；
  `w2_settings.ps1` 27/27；LayoutPlan 59/59；`tests\w2\bench` 全過（含方向讀寫與朝內像素檢查：視窗外與中間 alpha 0）。
- CPU／記憶體（30 秒，882×471 的測試視窗）：呼吸朝內 0.18–0.23%（全機）、流光朝內 0.60–1.06%（同一段時間朝外 0.80%）；working set 47–48 MB。
