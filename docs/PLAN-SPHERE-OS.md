# 球體 AI 系統（大更新規劃，草稿 v0）

2026-11-23 Keng：把球體 AI 變成一套「系統」——
- 用哪一家的 AI 當大腦都能登入（Claude、ChatGPT、Grok、其他）
- 衛星＝一個 AI 工作者，可以自己加；點衛星就打開它的終端機視窗看它在做什麼
- 脫離現在「開一堆終端機、ShoWork42 在旁邊看」的模式，所有工作都在這套系統裡跑
- cool42（面板、守護程式、AI 閘門）全部併進來，變成系統的一部分

## 核心想法：系統不自己當大腦，而是「接各家官方的 AI 工作程式」

```
                 ┌──────────── 球體 AI 系統（一個 App）────────────┐
  登入／帳號 ──→ │  大腦接口（adapter）                              │
                 │   ├ Claude：claude（Claude Code，訂閱登入）        │
                 │   ├ ChatGPT：codex（OpenAI Codex CLI，ChatGPT 登入）│
                 │   ├ Grok：xAI（CLI 或 API 金鑰，待查）             │
                 │   └ 其他：Gemini CLI、本機模型…                    │
                 │  衛星＝一個工作者（一個 PTY 終端機＋它選的大腦）   │
                 │  球體＝總覽（狀態、額度、自檢、溫度、播報）        │
                 │  守門＝cool42 閘門＋額度＋自檢（所有大腦共用）     │
                 └──────────────────────────────────────────────────┘
```

為什麼接「官方工作程式」而不是自己寫一個 AI 迴圈：
- 登入直接用各家自己的（Claude Max／ChatGPT Plus 訂閱），不用管 API 金鑰、不用按 token 另外付錢
- 工具、權限、記憶、更新都由各家維護，我們只做「外殼＋總覽＋守門」
- 點衛星看到的就是那家 AI 原本的終端機畫面（Claude Code 的 okle42 樣式也照樣在）

## 分階段（每階段做完都能用，不會半套）

| 階段 | 內容 | 驗收 |
|---|---|---|
| S1 衛星終端機 | 點衛星 → 系統內開一個真的終端機視窗（PTY），跑那個 session 的 `claude --resume`；「＋」加衛星＝開新工作者 | 從開新衛星到做完一件事，全程不開 Ghostty |
| S2 大腦接口 | adapter 介面：啟動、續接、狀態（忙／等你／做完）、額度；先做 Claude，再做 Codex（ChatGPT） | 同一顆球上同時有 Claude 衛星和 ChatGPT 衛星 |
| S3 登入 | 第一次開系統：選大腦 → 走各家官方登入（`claude` 登入、`codex login`），之後記住 | 新電腦裝好就能登入使用 |
| S4 cool42 併入 | 閘門改成系統內建（所有大腦開重工作前都問）；守護程式（要最高權限控風扇）改由系統安裝與管理 | 不裝 cool42 也有完整功能 |
| S5 獨立 App | 新名字、新圖示，脫離 ShoWork42 戰情中心殼；ShoWork42 退成這套系統的一個分頁或停用 | 只開這個 App 就能工作 |

## 要 Keng 決定的事

1. **衛星打開的視窗**：①真的終端機畫面（推薦：跟現在看到的一模一樣，各家 AI 都適用） ②聊天式工作視窗（現有 work.html，比較好看但只有 Claude 能用）
2. **終端機元件**：要用 xterm.js（網頁終端機，兩平台共用）或 SwiftTerm（Mac 原生，Orbit42 原本選的）——兩個都要新裝套件，依規矩先問
3. **Grok 的「Gork bot 結構」**：是指 xAI 的 Grok，還是某個叫 Gork 的 bot 專案？要接的是它的哪個部分（登入／對話／它的多工作者架構）？
4. **系統名字**：沿用 ShoWork42、用 Orbit42（原本的自製終端機名字），還是新取？
5. **cool42 守護程式併入**：cool42 已公開發布（v1.1.0），併進來後公開版要繼續維護，還是只留在系統裡？
