# ShoWork42 · M1 計畫：Claude Code + Ghostty 每天能用

> 目標：Kang 日常用一整天，零誤報、零漏報，不拖累 Claude，也不打擾其他 App。
> Terminal.app、iTerm2、tmux 的對應法在 M0 已驗證，M1 一起接上（程式碼共用），但每天的驗收以 Ghostty 為主。

## 架構

```
Claude Code hook ──▶ showork emit <state>   （CLI，200ms 內一定結束、永遠 exit 0）
                        │ Unix socket（~/Library/Application Support/ShoWork42/agent.sock）
                        ▼
                 ShoWorkAgent（常駐、無 Dock 圖示）
                   ├─ Resolver：tty → 終端機／視窗 wid／分頁（Ghostty、Terminal、iTerm2、tmux）
                   ├─ StateStore：每個 tty 一個狀態；每個視窗取 紅 > 金 > 紫
                   ├─ GlowManager：每個視窗一圈光暈；單一看門狗；全螢幕改畫螢幕邊緣細光
                   └─ ClearWatcher：視窗取得焦點＋該分頁被選中，或在前景視窗裡按鍵／點擊 ⇒ 清除 金／紅
```

## 狀態機（每個 tty）

| 事件 | 結果 |
|---|---|
| `working`（UserPromptSubmit、PreToolUse） | 紫 |
| `done`（Stop） | 金；如果該分頁正在前景而且視窗有焦點，就直接清除（你正在看，不必提示） |
| `input`（Notification：權限或提問） | 紅 |
| `clear`（SessionEnd，或 ClearWatcher 觸發） | 無 |
| 紫色持續超過 30 分鐘沒有新事件 | 保持紫，但 M2 的通用後備會用輸出動靜複核 |
| tty 消失（程式結束） | 無 |

## 驗收判準

1. **正確性**：單元測試涵蓋狀態機和優先序的所有轉換；端對端測試用 `claude -p --settings <測試設定>` 實際跑，紫 → 金 → 清除都要由驗證器確認。
2. **不拖累**：agent 沒在跑時 `showork emit` 仍在 200ms 內結束，而且 exit 0；hook 加上去後，Claude 回應的時間差不超過 50ms。
3. **省資源**：10 個視窗、閒置時，CPU 總量 < 0.5%，記憶體 < 40 MB。
4. **樣子**：柔和外暈約 12pt；紫色緩慢呼吸；金色恆亮；紅色微脈動；開啟「減少動態效果」時不動畫。**Kang 看過點頭才算數。**
5. **拖曳**：拖曳途中光暈不落後（高頻跟隨，或拖曳時淡出）。
6. **安裝和移除**：寫入 `~/.claude/settings.json` 前先備份，只做合併，和 ghosts 的 hooks 共存；一鍵移除後恢復原狀。**真正寫入 Kang 的設定前要先問。**

## 順序

1. Swift 套件骨架：ShoWorkCore（狀態機）＋ `showork` CLI ＋ 單元測試
2. ShoWorkAgent：socket、Resolver、StateStore
3. GlowManager（從 M0 原型收斂）＋ ClearWatcher
4. Claude hooks 轉接＋測試設定檔＋端對端
5. 樣子調校 → **Kang 過目**
6. 資源量測、安裝／移除工具 → **Kang 同意後裝到自己的設定**，日用一天
